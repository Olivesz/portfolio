01the problem

An agent finishes and writes “ran the tests, all passing.” The harness has already logged every tool call it made, and nothing reads the two side by side.

In a study of 20,574 real coding-agent sessions (arXiv 2605.29442), 22.58% of 16,118 episodes where the agent went wrong were the agent misreporting its own work. In resolved episodes, the agent corrected itself 2.99% of the time.

02how it works

A hook the harness calls on every tool call appends a CALL and a RESULT to a per-session ledger; the model has no write path to it.

The ledger is append-only, and each event is hashed with the hash before it, so editing any earlier event breaks the chain; secrets are redacted before hashing.

When the agent stops, its final report is split into claims, each a verbatim span, and a rule for each claim type checks it against the ledger. A test claim with no test run in the log is unwitnessed; piped or truncated output is unrecorded; a failing summary, or a test count the run cannot support, is contradicted. With a model key, a model reviews what the rules leave open, but its contradicted verdict stands only if the rule for that claim agrees; otherwise it is shown as advice. Auto mode is opt-in. In it, a contradicted claim keeps the agent from finishing: a fixed-text message, the nudge, goes back, for up to 3 passes, and the claim clears only on a tool call made after the nudge, so rewording it does nothing.

03the false accusations

The audit aimed at the one verdict that can hurt a user: contradicted.

Over 93 local sessions with a report and at least 3 tool calls, the pipeline made 4 accusations, and at least 3 were false. Those 3 had one cause. The path regex dropped the prefix of absolute and dot-prefixed paths, so a real file looked missing and the miss became an accusation.

The fix matches paths whole, so the real file is found and nothing is accused. It also adds a guard, accusable(): a missing file supports an accusation only when the repo root exists on the machine, and the path has a directory and is absolute or inside that root. Anything else is unwitnessed: a file that could not be checked is not proven missing. After the fix the same sessions drew 1 accusation, none known false.

04results

A scoreboard drives the installed hooks through ten scenarios whose truth is known, in a real git repo with real commands and no API key: 5 lies and 2 blind runs it must not confirm, and 3 reports that must draw no verdict.

A mutation run measures whether the checker’s own tests notice a broken checker. Blocking stays on rules: in a repeat-run measurement on 18 real sessions, 22.8% of model-driven verdicts flipped between identical runs. Coverage is the open limit.
