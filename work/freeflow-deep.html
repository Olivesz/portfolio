01 · the situation

Words wherever the cursor is

Dictation that works in any app has one job. You talk, and the words appear wherever the cursor is: a mail draft, a chat box, a code editor.

freeflow does that on a Mac, with Whisper running on the machine through whisper.cpp. No account, no cloud, $0 a month.

The words should show up while you talk, not after you stop. That is where it gets hard. Whisper only transcribes finished clips. To get words while you talk, the app runs it again every 350 ms on everything heard so far. Each run is a pass, and a later pass often changes words an earlier one got wrong.

Text already typed into another app can’t be quietly edited. Retyping gets the sentence right in the end, but wrong words flash on screen first, and every correction is a burst of backspaces sent into someone else’s app. The repo’s phone keyboard is a spike that types this way.

There’s a second cost. To revise its guesses, the model has to hear the speech again. Re-reading everything said so far on every pass gets slower the longer you talk.

02 · the idea

Three rules

Three rules handle both problems.

Read the recent audio again every 350 ms, but type a word only once two passes in a row agree on it. Never take a word back. And once enough agreed audio piles up, drop it from the front of what the model reads, keeping a short stretch for context.

The rest of the page builds this loop one stage at a time, in the order the audio meets them. The mac app is the one described. The Python prototype it was ported from uses the same rules with a few different constants, noted where they differ.

One pass is a guess. Two passes agreeing is a fact.

03 · the build

The loop, stage by stage

Each step below adds one stage, and each picture runs the same rules over the same scripted sentence.

step 01 · sound in

One growing buffer

The microphone delivers audio at whatever rate the hardware uses. whisper.cpp wants 16,000 samples a second, one channel, as floating-point numbers. So every block from the mic is converted the moment it arrives and appended to one buffer that only grows.

The loop that runs the model never touches the microphone. It takes a copy of the buffer when it needs one.

step 02 · the tick

Three gates before every pass

A loop wakes every 350 ms, copies the buffer from the window’s start, and decides whether the model should see it at all.

Three gates come first, because Whisper doesn’t return nothing on silence. It fills silence with phrases like “thank you”.

step 03 · the model

Words with times

whisper.cpp runs the base.en model with beam search and is told to end a segment after every word. So each word comes back with its own start and end time.

Those times count from the window’s start, so the window’s offset is added back to place each word in the whole utterance. Tokens that aren’t speech, like [BLANK_AUDIO], a sound in parentheses or a lone full stop, are dropped here. Whisper learned them from subtitles.

step 04 · agreement

Type only what two passes agree on

This is the rule the whole app rests on, called LocalAgreement-2. Each pass is compared with the one before it, word by word from the front, ignoring case and spaces.

Words that match are committed and typed. The first mismatch stops the comparison, and everything from there on waits for the next pass.

step 05 · no repeats

Never type a word twice

Every pass re-reads audio whose words are already typed, so those words come back. Two checks remove them. By time: anything that starts before the last typed word ends, less a tenth of a second, is dropped. By text: if the first new words repeat the last typed ones, up to six of them, they’re dropped too.

The text check exists because whisper.cpp’s timestamps are coarse, so a typed word can come back a little late and slip past the time check.

step 06 · trimming

Trim the window

Once more than 3.0 seconds of typed audio sits in the window, the window’s start jumps forward to 1.5 seconds before the end of the last typed word. The model keeps a little context and never re-reads the rest.

The staircase from fig 3 becomes a sawtooth.

step 07 · typing

Typing into the focused app

Words are typed as synthetic key events. Each event carries a Unicode string of up to 20 characters, so the text arrives intact in any app that accepts typing. This needs the Accessibility permission.

Nothing is ever taken back, so the backspace count stays at 0.

step 08 · stopping

Stopping cleanly

Silence ends it in either mode. After a 400 ms grace, every tick whose last 350 ms is below the floor adds 350 ms to a silence clock. Speech resets it. At 1,500 ms it stops, so the fifth quiet tick in a row ends it. In hold mode, letting go of the key ends it sooner.

Either way, the stop only sets a flag. The loop finishes its turn, trims the quiet off the tail, and runs one last pass that types whatever was still waiting.

04 · what broke

Swallowed words

Words went missing mid-sentence. A phrase spoken clearly never appeared, and the words after it did.

There are two places a word can vanish: the microphone never delivered it, or the model never wrote it down. A small diagnostic log separates the two. The picture below plays a scripted skip through both checks and through the rules above.

The comment on the fix names the window. At 8.0 seconds of typed audio with 2.0 kept, whisper.cpp fell behind real time and skipped phrases, “~2s” at a time in the comment’s words, and the next trim made each loss permanent.

The mac app now trims at 3.0 seconds, keeps 1.5, and decodes with beam search. The Python prototype still uses 8.0 and 2.0.

05 · results

What is tested, and what isn’t

The streaming rules were first written in Python with no model or microphone inside them, so they can be tested anywhere.

All 29 tests passed on CI at the pinned commit. The Swift app has no test target. A hidden self-test mode replays a 16 kHz recording through the real model and streamer in 0.35 s steps; none of its output is in the repo. Nothing in the repo measures delay, accuracy or battery.

  • 29tests passed on CIPython core, at 6d541e6
  • 0backspaces, everappend-only by design
  • 234 saudio re-read in 30 sscripted, against 1,309 s untrimmed

The ideas fit on one card: copy the buffer every 350 ms, type only what two passes agree on, never take a word back, and keep the window short.
