01the problem

Neither chat site knows what was said on the other.

Projects, preferences and background get typed again in every new thread. inf-mem keeps one memory store that works across ChatGPT and Claude and offers it before a prompt is sent.

02how it works

A Manifest V3 Chrome extension runs on ChatGPT and Claude. On Enter or the send button it holds the prompt and asks a local FastAPI backend for related memories. The backend embeds the prompt with a small ONNX embedding model, no PyTorch.

Memories under cosine 0.35 are dropped. The rest rank by similarity × (1 + importance/10), and at most 5 come back. A review panel lists them with two buttons, ‘send with memory’ and ‘skip memory’, plus ‘compress and send’ when compression is on (it is off by default). Sent with memory, the list goes in front of the prompt as a labelled context block.

When a reply appears, the background worker posts prompt and reply to the backend without waiting, and the backend sends them to Groq’s llama-3.1-8b-instant. The model returns typed memories (fact, project, preference, episode) with an importance from 1 to 10. A candidate above cosine 0.85 against a stored memory replaces it only when it is more important or longer; otherwise it is skipped. Memories live in SQLite plus a NumPy matrix under ~/.inf_mem.

03the ID file

A store that worked all session crashed on the next start.

Vectors and IDs sit in two .npy files, row for row. The first version saved the ID list as a pickled object array, but the store loads both files with pickle off, and NumPy will not read an object array that way. Within one run the IDs stay in memory, so the crash came only after a restart: the backend builds the store at startup, and the failed load stops it.

IDs now save as a plain string array, pickle off on both sides. A test opens a second store on the same directory and checks that the memory and a 1 × 384 matrix come back.

04results

The repository holds no recall or latency measurement; the test suite is the evidence.

  • 18tests, all passedon Python 3.11 and 3.12 at 2f86999; no network, LLM faked
  • ~130 MBembedding model, downloaded oncebge-small-en-v1.5 on ONNX Runtime, no PyTorch

The suite covers models, storage, retrieval and compression, with the LLM client faked, the embedding patched and the store redirected to a temporary directory. CI runs ruff and pytest. The extension popup reads live health and the memory count from the running backend.
